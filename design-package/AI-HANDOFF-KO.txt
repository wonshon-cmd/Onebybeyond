이 패키지로 ONE TO BEYOND 웹사이트를 완성하고 배포해주세요.

1. README-KO.md와 DESIGN-SYSTEM.md를 먼저 읽으세요.
2. 디자인 기준은 reference/approved-design.html입니다. 사용자는 오프화이트 Editorial Letter의 실제 한글 글꼴, 목차, 숫자, 필기체, 여백을 최종 승인했습니다. 로고만 오렌지·그린 두 사선의 ONE TO BEYOND로 고정합니다. 미리 만든 다른 디자인으로 다시 바꾸지 마세요.
3. index.html/style.css/app.js/assets는 디자인 시작점입니다. admin.html은 구현된 관리자 기능을 이식할 참고 코드입니다. admin.html의 공개 화면 스타일은 최종 디자인 기준이 아닙니다.
4. 이전 기능 요구를 반영하여 하나의 사이트로 통합하세요: 표지 후 본문 전체 스크롤, 소식지 목차 선택, 이야기 하트, 기도제목 아멘 토글, 공유, 댓글/마음 나눔, 유튜브 링크+미리보기, 사진 갤러리.
5. 관리자: 이메일/비밀번호와 실제 인증, 모바일 편집, 초안 저장/자동저장, 공개 반영 별도, 섹션 사진·갤러리 다중업로드·사진별 설명/좌표, 본문 편집, 소식지 새로 만들기. 승인된 글꼴을 기본으로 유지하세요. 오프라인 초안 JSON 내보내기/불러오기 로직을 참고하세요.
6. 연락처: 이름/이메일/그룹/비공개 노트. 기본 수신자 전체 선택, 개별 제외, 그룹 선택. 발송 전 대상/내용 미리보기. 아직 실제 이메일 발송은 연결되지 않았습니다.
7. 실제 사용자 공용 좋아요/아멘/댓글, 여러 기기의 편집 연속성은 인증+데이터베이스+파일 저장소를 구현하세요. 로컬 데모 로그인은 운영용 보안이 아닙니다. API 비밀키를 클라이언트 HTML에 넣지 마세요. 공개 페이지에서 관리자 주소록/노트가 노출되지 않도록 하세요.
8. 카카오는 우선 사용자가 친구/대화방을 직접 선택하는 공유입니다. 관리자 일괄 자동발송은 별도의 비즈메시지 연결/템플릿 검토가 필요합니다. 현재 연결됐다고 표시하지 마세요.
9. 후원/결제/Stripe는 추가하지 마세요. 기존 디자인 참고 파일에 남은 데모 링크가 있다면 운영본에서 제거하세요.
10. 저장/공개/발송/업로드 오류를 처리하고 모바일 390px에서 확인하세요. 하트/아멘/목차/댓글/초안 저장/이미지/유튜브 링크가 실제 동작하는지 테스트한 뒤 배포하세요. 어떤 백엔드를 썼는지와 실제 연결된 기능/미연결 기능을 정확히 안내하세요.

현재 이 패키지는 정적 시작점 + 관리자 구현 참고 자료입니다. 배포 가능한 완성 백엔드라고 가정하지 말고 필요한 통합 작업을 수행하세요.
